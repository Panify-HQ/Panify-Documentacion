E-001

Autenticación

POST

/api/v1/auth/usuarios

Usuario

Registra nuevos usuarios en la plataforma (clientes).

N/A

Body: 

  • nombre (cadena, obligatorio).
  • apellido (cadena, obligatorio).
  • correo (cadena, obligatorio, único).
  • contrasena (cadena, obligatorio, mín. 8 caracteres).
  • telefono (cadena, obligatorio).
  • direccionEntrega (cadena, obligatorio).
  • barrio (cadena, obligatorio). 
  • El correo electrónico debe ser único en la base de datos.
  • La contraseña se almacena encriptada (hash).
  • Por defecto se asigna el rol de 'Cliente' y el estadoCuenta como 'Activo'.

201 Created — Confirma el registro del nuevo usuario y retorna sus datos creados (ID de usuario, nombre, correo, rol) sin exponer la contraseña.

  • CP-01 (Éxito): 201 Created al enviar todos los datos obligatorios con un correo no registrado.
  • CP-02 (Validación): 400 Bad Request si faltan campos obligatorios o la contraseña no cumple la longitud mínima.
  • CP-03 (Conflicto): 409 Conflict si el correo electrónico ya existe registrado en el sistema.
  • CP-04 (Servidor): 500 Internal Server Error ante fallos en la transacción de base de datos.

E-002

Autenticación

POST

/api/v1/auth/login

Usuario

Válida correo y contraseña para autenticar al usuario y generar su token de sesión.

N/A

Body: 

  • correo (cadena, obligatorio).
  • contrasena (cadena, obligatorio).
  • El correo y la contraseña deben coincidir con un registro activo.
  • Si la cuenta está en estado Inactivo, se deniega el acceso.
  • Devuelve el token de autenticación junto con los datos de perfil y rol del usuario.

200 OK — Devuelve el token JWT de sesión junto con la información de perfil y el rol asignado (Cliente, Panadero, Domiciliario, Administrador, Super Administrador).

  • CP-01 (Éxito): 200 OK al ingresar correo y contraseña válidos de una cuenta activa.
  • CP-02 (Validación): 400 Bad Request si alguno de los campos requeridos está vacío o mal formado.
  • CP-03 (Autenticación): 401 Unauthorized si el correo no existe o la contraseña no coincide.
  • CP-04 (Acceso denegado): 403 Forbidden si la cuenta del usuario se encuentra en estado Inactivo.
  • CP-05 (Servidor): 500 Internal Server Error por fallos de red o conexión a la base de datos.

E-003

Autenticación

POST

/api/v1/auth/recuperar-contraseña

Usuario

Envía un token o código temporal al correo registrado para iniciar el proceso de cambio de contraseña.

N/A

Body: 

  • correo (cadena, obligatorio).
  • El correo electrónico debe existir previamente en la base de datos del sistema.
  • Genera un token temporal con tiempo límite de expiración (ej. 15 minutos).
  • Envía el mensaje con el token o enlace de recuperación al correo del usuario.

200 OK — Retorna un mensaje informativo notificando que se ha enviado el token o enlace de recuperación al correo registrado.

  • CP-01 (Éxito): 200 OK al enviar un correo válido y registrado en la plataforma.
  • CP-02 (Validación): 400 Bad Request si el correo tiene un formato inválido o está vacío.
  • CP-03 (Recurso no encontrado): 404 Not Found si el correo ingresado no pertenece a ningún usuario registrado.
  • CP-04 (Servidor): 500 Internal Server Error en caso de falla de envío del servicio SMTP de correo o error de servidor.

E-004

Autenticación

POST

/api/v1/auth/restablecer-contraseña

Usuario

Recibe el token de validación y la nueva contraseña para actualizar las credenciales de acceso.

N/A

Body: 

  • token (cadena, obligatorio).
  • nuevaContrasena (cadena, obligatorio, mín. 8 caracteres).
  • confirmarContrasena (cadena, obligatorio). 
  • El token de validación debe estar activo y no haber superado su tiempo de expiración. nuevaContrasena y confirmarContrasena deben coincidir exactamente.
  • Al actualizar la clave, la nueva contraseña se almacena encriptada y el token temporal se invalida automáticamente.

200 OK — Confirma la actualización exitosa de la contraseña en el sistema e invalida el token temporal de recuperación.

  • CP-01 (Éxito): 200 OK enviando un token vigente con una nueva contraseña válida y coincidente.
  • CP-02 (Validación): 400 Bad Request si las contraseñas no coinciden o la clave es débil.
  • CP-03 (Conflicto): 409 Conflict si el token es inválido, ya fue utilizado previamente o ha expirado.
  • CP-04 (Servidor): 500 Internal Server Error en caso de falla de persistencia al actualizar el registro en la base de datos.

Permite crear y registrar un nuevo usuario en el sistema directamente desde el panel de administración.

N/A

Body: 

  • nombre (cadena, obligatorio).
  • apellido (cadena, obligatorio).
  • correo (cadena, obligatorio, único).
  • contrasena (cadena, obligatorio, mín. 8 caracteres).
  • telefono (cadena, obligatorio).
  • idRol (número entero, obligatorio).
  • direccionEntrega (cadena, opcional si es Cliente).
  • barrio (cadena, opcional si es Cliente).

  • CP-04 (Permisos): 403 Forbidden si la acción es ejecutada por un Cliente, Panadero o Domiciliario, o si un Administrador intenta crear a otro Administrador sin ser Super Administrador.

Body: 

  • estadoCuenta (cadena, obligatorio: Activo o Inactivo).

200 OK — Confirma el cambio de estado de la cuenta del usuario e informa el nuevo estado asignado.

  • CP-01 (Éxito): 200 OK al cambiar el estado de cuenta de un usuario a Inactivo o Activo.
  • CP-02 (Validación): 400 Bad Request si el valor de estadoCuenta enviado no corresponde a Activo o Inactivo.
  • CP-03 (Autenticación): 401 Unauthorized sin token activo de sesión.
  • CP-04 (Permisos): 403 Forbidden si un rol no administrativo intenta cambiar el estado o si un Administrador intenta inactivar a otro Administrador.
  • CP-05 (Recurso no encontrado): 404 Not Found si el usuario solicitado no existe.
  • CP-06 (Servidor): 500 Internal Server Error por fallos internos del servidor.

  • CP-03 (Autenticación): 401 Unauthorized si se realiza la petición sin autenticar.
  • CP-04 (Permisos): 403 Forbidden si la petición la realiza un rol no autorizado o si un Administrador intenta asignar el rol de Administrador sin ser Super Administrador.
  • CP-05 (Recurso no encontrado): 404 Not Found si el idUsuario especificado no existe.

  • CP-02 (Validación): 400 Bad Request si los parámetros de consulta idDomiciliario o estadoRuta son inválidos.
  • CP-03 (Autenticación): 401 Unauthorized si la petición no incluye un token de sesión activo.
  • CP-04 (Permisos): 403 Forbidden si un Domiciliario intenta acceder a la ruta asignada a otro usuario.
  • CP-05 (Recurso): 404 Not Found si no se encuentra ninguna ruta registrada para el Domiciliario especificado.
  • CP-06 (Servidor): 500 Internal Server Error ante fallos de conexión o consulta SQL.
